# قائمة تفعيل الإنتاج لمنصة مِزَاد

## حالة الكود الحالية

هذه المستودعات تتضمن أساس Laravel للكتالوج والمزادات الذرية والطلبات والمحافظ والشحن، إعداد Render متعدد الخدمات، وواجهة Marketplace قادرة على التحول إلى بيانات Laravel عند تهيئة عنوان المتصفح. لا تحتوي المستودعات على مفاتيح دفع أو شحن أو بيانات مالية حقيقية، ولا ينبغي إدخالها في Git أو ملفات الواجهة.

| نطاق التفعيل | ما هو جاهز في الكود | ما يلزم قبل الإطلاق الحي |
|---|---|---|
| Laravel وPostgreSQL | الترحيلات، سياسات البلد، اختبارات PostgreSQL، وحزمة Render | إنشاء خدمات Render، ضبط متغيرات البيئة، وتنفيذ `php artisan migrate --force` مرة واحدة |
| Redis وHorizon | إعداد صفوف ووكر Horizon | ربط Redis الداخلي وتأكيد أن خدمة Horizon متصلة بالطابور |
| Reverb | إعداد القنوات والبث بعد الالتزام | تعيين روابط Reverb العامة والداخلية وفتح اتصال WebSocket من النطاق العام |
| Meilisearch | إعداد Scout وعنوان داخلي | تعيين مفتاح رئيسي قوي، تشغيل import للفهرس عند الحاجة، ومراقبة صحة الخدمة |
| S3-compatible storage | تكوين قرص خاص للوسائط | توفير bucket خاص ومفاتيح وصول وحظر القراءة العامة افتراضياً |
| Marketplace React | محول API، احتياط بيانات عرض موسوم، اختبارات فشل الاتصال | تعيين `VITE_LARAVEL_API_BASE_URL` إلى رابط Laravel العام وتأكيد CORS وSanctum |
| المدفوعات | عقد بوابة، تسوية webhook مكررة، دفتر محفظة | اختيار مزود لكل بلد، مفاتيح حية، توقيع webhook، نطاقات callback، واختبارات sandbox |
| الشحن | حالات تنفيذ وشحن واستلام ذاتي | اختيار ناقل/ناقلين لكل بلد، مفاتيح API، قواعد مناطق الشحن، واختبارات tracking |

## تسلسل تفعيل Render

1. أنشئ Blueprint من `render.yaml` من فرع محمي، وراجع قائمة الخدمات: تطبيق الويب، Horizon، Reverb، scheduler، PostgreSQL، Redis، وMeilisearch.
2. أنشئ القيم السرية من لوحة Render فقط. القيم الدنيا هي `APP_KEY`، `APP_URL`، `DB_*` أو `DATABASE_URL`، `REDIS_URL`، مفاتيح Reverb، مفتاح Meilisearch، ومفاتيح S3-compatible storage.
3. عيّن `APP_ENV=production`، `APP_DEBUG=false`، `LOG_CHANNEL=stderr`، `QUEUE_CONNECTION=redis`، و`CACHE_STORE=redis`، ثم استخدم نطاق Laravel العام في `APP_URL`.
4. نفّذ الترحيلات من مهمة إصدار محكومة، ثم شغّل seeder الصلاحيات بصورة مقصودة. لا تشغّل بيانات مستخدمين أو منتجات تجريبية في بيئة الإنتاج.
5. أنشئ أول حساب `GLOBAL_SUPER_ADMIN` من خلال عملية داخلية موثقة، تحقق من البريد، ثم راجع دخول `/admin` على نطاق Laravel نفسه.
6. افحص `/up` أو مسار الصحة المتفق عليه لخدمة الويب، وراقب خدمات Horizon وReverb وscheduler منفصلة قبل نشر الواجهة.

## تفعيل الواجهة الحية

1. بعد أن يصبح نطاق Laravel العام متاحاً، اضبط `VITE_LARAVEL_API_BASE_URL` على رابط HTTPS كامل مثل `https://api.example.com`.
2. شغّل اختبار الاتصال المشروط في الواجهة، وتأكد أن `GET /api/marketplaces/countries` ينجح من المتصفح.
3. افتح Marketplace، اختر دولة، وتأكد من إرسال ترويسة `X-Marketplace-Country` رقمية في استدعاءات البحث والمزادات والتفاصيل وسجل المزايدات.
4. أكمل تكامل جلسة Sanctum بين واجهة Marketplace ونطاق Laravel قبل تفعيل إنشاء المنتجات أو إرسال مزايدات أو سحوبات حية من الواجهة.
5. لا تحذف بيانات العرض المؤقتة قبل اجتياز فشل API واختبارات العودة الاحتياطية في بيئة staging؛ هي موجودة لحماية تجربة القراءة فقط عند تعطل الاتصال.

## تفعيل الدفع والشحن

> لا يصبح الدفع أو الشحن حياً بمجرد نشر الكود؛ يتطلب كل بلد مزوداً مرخصاً وحساباً موثقاً وبيانات سرية مخصصة.

1. حدد بلدان الإطلاق الأول، عملاتها، والمزود الأساسي والاحتياطي لكل بلد.
2. نفّذ محول بوابة دفع حقيقي يحقق توقيع webhook على مستوى الإنتاج، ويطابق transaction والمبلغ والعملة قبل التسوية.
3. سجّل مسارات webhook من لوحة المزود، وأضف سر التوقيع في Render، ثم اختبر replay ورفض التوقيع الخاطئ ورفض العملة الخاطئة.
4. أضف موفر شحن حقيقي لكل بلد، واقصر مفاتيحه على الخادم، ثم اختبر إنشاء الشحنة والتتبع والتسليم والاستلام الذاتي على staging.
5. راجع سياسات رد الأموال والعمولات والسحوبات والضرائب مع مسؤول قانوني/مالي محلي قبل تمكين تسويات فعلية.

## بوابة الإطلاق

- [ ] عنوان Laravel HTTPS صالح ومتاح للمتصفح
- [ ] جميع أسرار Render مخزنة في إعدادات الخدمات، وليس في Git
- [ ] نجاح الترحيلات وبيانات الأدوار على الإنتاج
- [ ] فحص web / Horizon / Reverb / scheduler / Redis / Meilisearch ناجح
- [ ] رابط الواجهة إلى Laravel، CORS، وسياق البلد متحققون
- [ ] جلسة Sanctum ونموذج حساب موحد مختبران من المتصفح
- [ ] مزود دفع وwebhook حقيقيان لكل بلد إطلاق
- [ ] موفر شحن وتتبّع حقيقيان لكل بلد إطلاق
- [ ] اختبار مزايدات متوازية متعدد العمال على staging
- [ ] مراجعة أمنية نهائية، سجلات ومراقبة وتنبيهات، وخطة rollback

لا يُعلن إطلاق تجاري كامل قبل إغلاق جميع عناصر بوابة الإطلاق.
