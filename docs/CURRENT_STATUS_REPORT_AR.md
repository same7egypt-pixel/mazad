# تقرير الحالة الحالي — منصة مِزَاد متعددة الدول

**تاريخ التحديث:** 22 أغسطس 2026  
**نطاق التقرير:** جاهزية تقنية للنشر التجريبي وبيئة Staging، وليست موافقة لإطلاق تجاري عام.  
**رابط واجهة المعاينة:** [aucmarket-affimzi4.manus.space](https://aucmarket-affimzi4.manus.space)

## الملخص التنفيذي

المنصة أصبحت في مرحلة **جاهزية تقنية متقدمة للتجربة والنشر المرحلي**. الخلفية هي Laravel مستقلة متعددة الدول، مع PostgreSQL وRedis/Horizon وReverb وMeilisearch وتخزين S3-compatible. وتطبق واجهاتها المقيدة سياق دولة إلزامياً، كما تحافظ الخدمات على ملكية البائع وعزل البلد في دورة المنتج والمزاد والطلب والشحن والمحفظة.

تتضمن واجهة Marketplace العربية صفحات الاستكشاف، تفاصيل المزاد، الحساب، ومسار بائع من خطوتين. أُضيف محول جلسة Laravel صريح يعتمد Token Sanctum في `sessionStorage` لهذه التجربة الفنية: دخول وخروج وفحص المستخدم الحالي، مع إرسال `Authorization: Bearer` وبلد السوق في كل طلب محمي، ومسح الرمز محلياً عند الخروج أو استجابة `401`. عندما يتوفر عنوان Laravel صالح وحساب Laravel، يستطيع المسار إنشاء منتج، رفع وسائطه الخاصة، وإرساله للمراجعة. كما أضيفت قائمة حية لمنتجات البائع لا تسمح بجدولة المزاد إلا لمنتج يملكه البائع، حالته `approved`، ولا يرتبط بمزاد سابق؛ وتبقى خدمة Laravel هي السلطة النهائية للتحقق من الملكية والحالة والتوقيتات.

> رابط المعاينة الحالي يعرض واجهة React مع بيانات عرض بديلة موسومة بوضوح عند غياب Laravel. لا يمثل تشغيل خدمة Laravel حية، ولا تفعيلاً لمدفوعات أو شحن أو مزايدات مالية فعلية.

## ما هو متاح حالياً

| السطح | الحالة التقنية | الحدود التشغيلية الحالية |
|---|---|---|
| `/` و`/auction/:id` | واجهة عربية متجاوبة لاكتشاف المزادات والتفاصيل وسجل المزايدات. تستبدل البيانات تلقائياً من Laravel عند صحة العنوان. | يرسل زر المزايدة مبلغاً حياً فقط مع جلسة Laravel صالحة، ثم يعيد جلب السعر والسجل من الخادم؛ ويحجب الادعاء بالنجاح عند رفض API. |
| `/account` | يعرض المحافظ والطلبات والتنبيهات من Laravel عند توفر جلسة Laravel وسياق بلد؛ ويستخدم عرضاً بديلاً موسوماً مع توجيه دخول واضح عند غياب الجلسة. لا يعتمد على OAuth الواجهة لتحميل البيانات الحية. | لا تعتمد بيانات العرض كرصيد أو حالة طلب تجارية. |
| `/sell` | دخول Laravel صريح، إنشاء منتج، رفع وسائط خاصة، وإرسال للمراجعة عند الربط الحي؛ قائمة للمنتجات الحية وجدولة مقيدة بالمنتج المعتمد غير المرتبط بمزاد. لا يمر هذا المسار عبر OAuth الواجهة. | اختبارات الواجهة تحاكي جلسة حية؛ الاختبار الفعلي في متصفح ضد Laravel ينتظر عنوان API حقيقياً وحساباً تجريبياً. |
| `/admin` | لوحة Filament مقيدة بحساب نشط وبريد موثق ودور إداري. تدعم إدارة/عرض عناصر التشغيل ضمن نطاق البلد. | مورد المستخدمين للقراءة والدعم فقط؛ لا توجد واجهة تتجاوز خدمات المجال لتغيير الحالات الحساسة. |
| المسارات غير المعروفة | صفحة 404 عربية متسقة مع الهوية. | لا يوجد أثر تشغيلي. |

## الخلفية وطبقات الضبط

| المجال | المنجز في الكود | الضبط أو القيد المهم |
|---|---|---|
| البنية | Docker Compose محلي، Laravel/PHP 8.3، PostgreSQL، Redis، Horizon، Reverb، Meilisearch، وMinIO/S3-compatible. كما توجد Blueprint وصور تشغيل وإرشادات Render. | لم يتم نشر Render فعلياً لعدم توفر حسابه وأسراره ضمن المهمة. |
| سياق الدولة والوصول | ترويسة `X-Marketplace-Country` وسياق سوق وSanctum وSpatie RBAC وسياسات Laravel. | الحساب ذو سياق دولة مختلف يُرفض في قائمة منتجات البائع، واختبر ذلك آلياً. |
| المنتجات والوسائط | منتج مسودة، رفع خاص، انتقال للمراجعة، اعتماد/رفض، ومنع إرسال منتج للمراجعة دون وسيط واحد على الأقل. | سياسة المنتج تمنع بائعاً آخر من رفع وسيط خاص لمنتج لا يملكه حتى داخل الدولة نفسها؛ ولا تظهر مفاتيح الوسائط الخاصة للعموم كملفات منشورة. |
| المزادات | إنشاء مقيد بمنتج معتمد يملكه البائع، مزايدة ذرية، بدء/إغلاق مجدول، إلغاء آمن، وإنتاج طلب فائز بصورة idempotent. | يلزم اختبار تنازع متعدد العمليات حقيقي قبل الإطلاق العام. |
| الطلبات والدفع والشحن | طلبات، تسوية idempotent، قيود محافظ وسحوبات، وأنواع شحن خارجي/داخلي/استلام ذاتي مع انتقالات مضبوطة. | لا يوجد مزود دفع أو ناقل حي مضبوط بالأسرار النهائية. |
| الإدارة | موارد Filament للدول والمدن والفئات والمنتجات والمزادات والطلبات والشحنات والسحوبات والمستخدمين، مع عزل بلد لغير `GLOBAL_SUPER_ADMIN`. توجد أيضاً شاشة منفصلة لتعيين أدوار المسؤولين. | شاشة الأدوار لا يفتحها إلا `GLOBAL_SUPER_ADMIN` صاحب `roles.manage`، وقد اختبر رفض مشرف الدولة حتى عند منحه الإذن منفرداً؛ الحذف معطل في الموارد الجديدة لتجنب فقدان البيانات. |

## تحقق الإصدار الحالي

تم تنفيذ فحص TypeScript، حزمة Vitest، اختبارات Laravel على PostgreSQL، وتدقيق Composer. كما تمت معاينة `/sell` على سطح المكتب والهاتف؛ ظهر نموذج RTL بترتيب واضح ودون تجاوز أفقي في قياس الهاتف، بينما لا يظهر قسم المنتجات الحية في المعاينة لغياب API وجلسة Sanctum حقيقيتين.

| التحقق | النتيجة |
|---|---|
| `pnpm run check` | ناجح. |
| `pnpm test` | **13 ملفاً ناجحاً** و**ملف واحد متخطى عمداً**؛ الملف المتخطى يختبر عنوان Laravel بيئي حقيقي ولا ينفذ عند عدم وجود URL HTTPS صالح. |
| `php artisan test` | **42 اختباراً ناجحاً و146 تأكيداً** على PostgreSQL، بما يشمل دورة token الفعلية: دخول، طلب مستخدم محمي، إلغاء token، ثم رفضه بعد الإلغاء. |
| `composer audit` | لا توجد تنبيهات ثغرات في الاعتمادات. |
| `./vendor/bin/pint --dirty` | ناجح. |
| الفحص المرئي | موثق في [ملاحظات الفحص المرئي](./QA_VISUAL_CHECK.md). |

## قرار الجاهزية

| القرار | الحالة | التفسير |
|---|---|---|
| نشر تقني إلى Staging على Render | **جاهز للتحضير** | ملفات Blueprint، صورة التشغيل، قوالب البيئة، وأدلة التشغيل موجودة؛ النشر نفسه يتطلب حساب Render وأسراره. |
| تجربة واجهة Marketplace المعروضة | **متاح الآن** | الواجهة المنشورة قابلة للتصفح، وتوضح عندما تستخدم بيانات عرض بديلة. |
| ربط Laravel الحي في المتصفح | **مهيأ برمجياً ومتحقق محلياً وغير متحقق خارجياً** | دورة token اختبرت محلياً في API، كما توجد جلسة `sessionStorage` ودخول وخروج وفحص مستخدم في الواجهة؛ لكن لا يوجد عنوان Laravel HTTPS صالح أو حساب Staging للتحقق end-to-end. |
| إطلاق تجاري ودفع حقيقي | **غير معتمد** | يحتاج قرار الدول، مزود دفع، أسرار Webhook، ناقلين، تخزين إنتاجي، وفحوص أمن وأداء وتنازع. |

## متطلبات الإطلاق التجاري المتبقية

| الأولوية | ما يحتاجه المالك أو بيئة الإنتاج | سبب عدم إمكانية افتراضه داخل الكود |
|---|---|---|
| حرجة | عنوان Laravel API عبر HTTPS، وإعداد `VITE_LARAVEL_API_BASE_URL`. | هو شرط الاتصال الحي للواجهة؛ القيمة المتاحة سابقاً ليست URL صالحاً. |
| حرجة | اختيار نمط جلسة الإنتاج وضبط CORS. | المحول الحالي يستعمل Bearer token داخل جلسة المتصفح للتجربة؛ يظل قرار جلسة HTTP-only أو تدابير الحماية المكافئة مطلوباً قبل الإطلاق التجاري. |
| حرجة | دول الإطلاق، العملات، مزود الدفع لكل دولة، وأسرار Webhook. | لا يجوز تخمين سياسات المدفوعات أو أسماء المفاتيح أو بيانات التاجر. |
| حرجة | S3 أو مزود متوافق حقيقي ومفاتيحه وسياسات الوصول الخاصة. | رفع الوسائط الخاصة لا يكتمل تشغيلياً دون تخزين إنتاجي. |
| عالية | حسابات SPL أو Aramex أو DHL، المفاتيح، وسياسة المناطق والتسعير. | طبقة الشحن الحالية مجال/تكامل جاهز وليست اتصالاً بمزود حقيقي. |
| عالية | اختبار مزايدات متزامن من عدة workers، اختبار ضغط، مراجعة أمنية، وإعادة تشغيل WebSocket. | هذا يثبت السلوك تحت الحمل الواقعي، وليس فقط ضمن العملية الاختبارية. |

## الخطوة العملية التالية

يُوصى بإنشاء بيئة Staging على Render أولاً، ثم تعيين عنوان Laravel HTTPS الحقيقي في متغير الواجهة وتوصيل نطاقي الواجهة وAPI مع Sanctum وCORS. بعد تسجيل مستخدم تجريبي في Laravel نفسه، يجب اختبار دورة كاملة: إنشاء منتج، رفع وسيط خاص، مراجعة إدارية، اعتماد، جدولة مزاد، مزايدة، ثم طلب. بعد ذلك فقط يبدأ ضبط مزود الدفع والناقل للدولة الأولى وفق قائمة التفعيل التفصيلية.[1] [2]
