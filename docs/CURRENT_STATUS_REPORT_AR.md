# تقرير الحالة الحالي — منصة مِزَاد متعددة الدول

**تاريخ التحديث:** 23 أغسطس 2026
**نطاق التقرير:** جاهزية تقنية للنشر التجريبي وبيئة Staging، وليست موافقة لإطلاق تجاري عام.  
**رابط واجهة المعاينة:** [aucmarket-affimzi4.manus.space](https://aucmarket-affimzi4.manus.space)

## الملخص التنفيذي

المنصة أصبحت في مرحلة **جاهزية تقنية متقدمة للتجربة والنشر المرحلي**. الخلفية هي Laravel مستقلة متعددة الدول، مع PostgreSQL وRedis/Horizon وReverb وMeilisearch وتخزين S3-compatible. وتطبق واجهاتها المقيدة سياق دولة إلزامياً، كما تحافظ الخدمات على ملكية البائع وعزل البلد في دورة المنتج والمزاد والطلب والشحن والمحفظة.

في 23 أغسطس 2026، نُسخت قاعدة تجربة Render إلى مشروع Neon الحالي في Ohio عبر `pg_dump` و`pg_restore` مع تحقق من الجداول. ظهرت الجداول المرجعية وسجل النشاط في Neon، ثم فُعّل الاتصال الحي عبر `USE_NEON_DATABASE=true` مع الاحتفاظ بـ `DB_URL` الأصلي لقاعدة Render كخيار رجوع. فُحصت نقطة الصحة، واكتشاف سوق السعودية، وصفحة دخول Filament، والواجهة العامة الجديدة على Render بعد التحويل. لم تُحذف قاعدة Render بعد؛ حذفها يتطلب تأكيد مالك نهائي بعد اختبار دخول فعلي.

> في بيئة Render المجانية المنشورة حالياً تعمل التجربة عبر HTTP فقط، ولا تستخدم WebSocket أو Reverb أو Horizon أو Scheduler أو Redis. تحديث ودجات الإدارة الدوري كل 30 ثانية هو طلب HTTP عادي، وليس تحديثاً لحظياً.

تتضمن واجهة Marketplace العربية صفحات الاستكشاف، تفاصيل المزاد، الحساب، ومسار بائع من خطوتين. أُضيف محول جلسة Laravel صريح يعتمد Token Sanctum في `sessionStorage` لهذه التجربة الفنية: دخول وخروج وفحص المستخدم الحالي، مع إرسال `Authorization: Bearer` وبلد السوق في كل طلب محمي، ومسح الرمز محلياً عند الخروج أو استجابة `401`. عندما يتوفر عنوان Laravel صالح وحساب Laravel، يستطيع المسار إنشاء منتج، رفع وسائطه الخاصة، وإرساله للمراجعة. كما أضيفت قائمة حية لمنتجات البائع لا تسمح بجدولة المزاد إلا لمنتج يملكه البائع، حالته `approved`، ولا يرتبط بمزاد سابق؛ وتبقى خدمة Laravel هي السلطة النهائية للتحقق من الملكية والحالة والتوقيتات.

> رابط المعاينة الحالي يعرض واجهة React مع بيانات عرض بديلة موسومة بوضوح عند غياب Laravel. لا يمثل تشغيل خدمة Laravel حية، ولا تفعيلاً لمدفوعات أو شحن أو مزايدات مالية فعلية.

## ما هو متاح حالياً

| السطح | الحالة التقنية | الحدود التشغيلية الحالية |
|---|---|---|
| `/` و`/auction/:id` | واجهة عربية متجاوبة لاكتشاف المزادات والتفاصيل وسجل المزايدات. تستبدل البيانات تلقائياً من Laravel عند صحة العنوان. | يرسل زر المزايدة مبلغاً حياً فقط مع جلسة Laravel صالحة، ثم يعيد جلب السعر والسجل من الخادم؛ ويحجب الادعاء بالنجاح عند رفض API. |
| `/account` | يعرض المحافظ والطلبات والتنبيهات من Laravel عند توفر جلسة Laravel وسياق بلد؛ ويستخدم عرضاً بديلاً موسوماً مع توجيه دخول واضح عند غياب الجلسة. لا يعتمد على OAuth الواجهة لتحميل البيانات الحية. | لا تعتمد بيانات العرض كرصيد أو حالة طلب تجارية. |
| `/sell` | أُصلح إدخال وقت المزاد: وقت بداية مقترح بعد ساعة، ونهاية بعد 24 ساعة، ورفض واضح لنهاية تسبق البداية، مع توضيح أن المنتج المعتمد فقط قابل للجدولة. | الإصلاح منشور الآن على موقع Render العام واجتاز الاختبارات والبناء. يبقى التحقق التفاعلي بعد دخول بائع حقيقي مطلوباً؛ لا تُنشأ بيانات اختبارية لهذا الغرض. |
| `/admin` | لوحة Filament مقيدة بحساب نشط وبريد موثق ودور إداري. بُني مركز عمليات عربي RTL داكن يعتمد على بيانات قاعدة البيانات الفعلية: مؤشرات، مخططات مزادات وإيراد مفصول حسب العملة، إشارات تشغيل، جداول معاملات ومزادات نشطة، وسجل تدقيق. | استجاب مسار الدخول الحي بالثيم الداكن بعد تحويل Neon. لا يعرض المركز أرقاماً أو مراجعات أو تقييمات مختلقة؛ في قاعدة فارغة تظهر حالات فارغة. يظل اختبار دخول المدير الفعلي مطلوباً من المالك من دون مشاركة كلمة المرور. |
| المسارات غير المعروفة | صفحة 404 عربية متسقة مع الهوية. | لا يوجد أثر تشغيلي. |

## الخلفية وطبقات الضبط

| المجال | المنجز في الكود | الضبط أو القيد المهم |
|---|---|---|
| البنية | Docker Compose محلي، Laravel/PHP 8.3، PostgreSQL، Redis، Horizon، Reverb، Meilisearch، وMinIO/S3-compatible. توجد أيضاً Blueprint إنتاج كامل منفصل في `render.production.yaml`، وBlueprint تجربة مجاني افتراضي في `render.yaml` لا ينشئ سوى Laravel API وPostgreSQL ويستبعد Reverb والتحديثات اللحظية. `USE_NEON_DATABASE=true` يوجّه اتصال PostgreSQL الحي إلى Neon، بينما يبقى `DB_URL` لقاعدة Render محفوظاً للرجوع. | نُشرت خدمة تجربة فعلية على Render في `https://mazad-trial-api.onrender.com`؛ تظل النسخة المجانية اختبارية وتستبدل WebSocket والطوابير والبحث الخارجي بطلبات HTTP وPostgreSQL فقط. قاعدة Neon الحالية في Ohio، لذا توجد كلفة زمن شبكة إضافية مقارنةً بخدمة Render في Frankfurt. لا تحذف قاعدة Render قبل تأكيد المالك النهائي. |
| تهيئة المدير الأول | الأمر `marketplace:provision-first-admin` لا يعمل إلا عند تفعيل `FIRST_ADMIN_ENABLED` ووجود اسم وبريد صالح وكلمة مرور في متغيرات Render السرية. يزرع مسار البدء أدوار وصلاحيات RBAC قبل البيانات المرجعية وقبل إنشاء المدير، ثم يثبت دور `GLOBAL_SUPER_ADMIN` والبريد الموثق والحالة النشطة للحساب بصورة idempotent. | بعد أول دخول ناجح يجب تغيير كلمة المرور، ثم جعل `FIRST_ADMIN_ENABLED=false` وحذف `FIRST_ADMIN_PASSWORD` من Render وإعادة النشر؛ لا تحفظ أي كلمة مرور في Git أو التقرير. |
| سياق الدولة والوصول | ترويسة `X-Marketplace-Country` وسياق سوق وSanctum وSpatie RBAC وسياسات Laravel. | الحساب ذو سياق دولة مختلف يُرفض في قائمة منتجات البائع، واختبر ذلك آلياً. |
| المنتجات والوسائط | منتج مسودة، رفع خاص، انتقال للمراجعة، اعتماد/رفض، ومنع إرسال منتج للمراجعة دون وسيط واحد على الأقل. | سياسة المنتج تمنع بائعاً آخر من رفع وسيط خاص لمنتج لا يملكه حتى داخل الدولة نفسها؛ ولا تظهر مفاتيح الوسائط الخاصة للعموم كملفات منشورة. |
| المزادات | إنشاء مقيد بمنتج معتمد يملكه البائع، مزايدة ذرية، بدء/إغلاق مجدول، إلغاء آمن، وإنتاج طلب فائز بصورة idempotent. | اختبار PostgreSQL متعدد العمليات أثبت أن مزايدتين متطابقتين تقبلان واحدة فقط وتُرفض الأخرى بعد تحديث الحد الأدنى؛ يبقى اختبار الضغط واسع النطاق مطلوباً قبل الإطلاق العام. |
| الطلبات والدفع والشحن | طلبات، تسوية idempotent، قيود محافظ وسحوبات، وأنواع شحن خارجي/داخلي/استلام ذاتي مع انتقالات مضبوطة. يوجد محول HMAC JSON مرجعي يتحقق من توقيع Webhook قبل المعالجة واختبر إعادة الإرسال عبر API دون تكرار التسوية. | المحول المرجعي لا ينشئ رابط Checkout زائفاً؛ لا يوجد مزود دفع أو ناقل حي مضبوط بالأسرار النهائية. |
| الإدارة | موارد Filament للدول والمدن والفئات والمنتجات والمزادات والطلبات والشحنات والسحوبات والمستخدمين، مع عزل بلد لغير `GLOBAL_SUPER_ADMIN`. يوجد مركز عمليات ببطاقات KPI حقيقية، مخطط حالة المزادات، مخطط GMV والعمولة لكل عملة على حدة، إشارات مراجعة، جداول عمليات، سجل تدقيق، وتنقل مجموع بحسب السوق والمستخدمين والطلبات والمالية والشحن والأسواق والنظام. | شاشة الأدوار لا يفتحها إلا `GLOBAL_SUPER_ADMIN` صاحب `roles.manage`، وقد اختبر رفض مشرف الدولة حتى عند منحه الإذن منفرداً؛ الحذف معطل في الموارد الجديدة لتجنب فقدان البيانات. إيقاف/إلغاء/تمديد المزاد يمر بخدمة معاملات وقفل سجل وتدقيق السبب؛ لا توجد إجراءات تغيير مستخدمين حساسة خارج خدمة وسياسة مختبرتين. |

## تحقق الإصدار الحالي

تم تنفيذ حزمة Vitest وبناء Vite، واختبارات Laravel الكاملة، وبناء أصول Filament باستخدام ملف القفل، وتدقيق Composer. كما أضيف اختبار نطاق صريح لودجات مركز العمليات يثبت أن مخطط المزادات وسجل التدقيق لمشرف الدولة لا يعرضان بيانات دولة أخرى.

| التحقق | النتيجة |
|---|---|
| `pnpm run check` | ناجح. |
| `pnpm test` و`vite build` | **16 ملفاً ناجحاً و37 اختباراً**؛ وبناء الواجهة ناجح، بما فيه اختبار جدولة البائع ورسالة رفض الدخول الواضحة. |
| `php artisan test` | **72 اختباراً ناجحاً و276 تأكيداً**، بما فيه عزل ودجات مركز العمليات، خدمة إيقاف/إلغاء/تمديد المزاد، حدود Filament والصلاحيات، والتحويل الصريح القابل للرجوع إلى Neon. |
| `npm ci && npm run build` داخل Laravel | ناجح؛ أنتج أصل Vite للثيم الداكن، واعتمد على `package-lock.json` لكي يعيد Docker إنتاج نفس البناء. |
| `composer validate` و`composer audit` | ناجحان؛ لم تظهر تنبيهات ثغرات. |
| `git diff --check` | ناجح. |

## قرار الجاهزية

| القرار | الحالة | التفسير |
|---|---|---|
| نشر تقني إلى Staging على Render | **منشور ومتحقق** | تعمل الخدمة الحية عبر HTTPS بعد إصلاح بناء أصول Filament وسكربت البذر وأداة نقل PostgreSQL. فُحصت `/up` واكتشاف السوق وصفحة دخول `/admin` بعد التحويل إلى Neon. |
| تجربة واجهة Marketplace المعروضة | **متاح الآن على Render** | الموقع العام يعمل من Render Static Site؛ لا يعتمد النشر الحالي على Netlify. صفحة الدخول تحمّل سوق السعودية ورمزه، ورسالة رفض الدخول تميّز سوق الحساب المختلف عن بيانات الدخول الخاطئة من دون كشف معلومات حساسة. |
| ربط الخدمة الحية في المتصفح | **مضبوط بيئياً ومتحقق جزئياً خارجياً** | عنوان الخدمة في Render مضبوظ في إعداد الواجهة، وقد نجح اختبار المتصفح لاكتشاف سوق السعودية. ما زالت رحلة المتصفح الكاملة للدخول والبيع والمزايدة تنتظر حساباً حقيقياً يختبره مالكه في جلسته. |
| إطلاق تجاري ودفع حقيقي | **غير معتمد** | يحتاج قرار الدول، مزود دفع، أسرار Webhook، ناقلين، تخزين إنتاجي، وفحوص أمن وأداء وتنازع. |

## متطلبات الإطلاق التجاري المتبقية

| الأولوية | ما يحتاجه المالك أو بيئة الإنتاج | سبب عدم إمكانية افتراضه داخل الكود |
|---|---|---|
| حرجة | عنوان Laravel API عبر HTTPS، وإعداد `VITE_LARAVEL_API_BASE_URL`. | هو شرط الاتصال الحي للواجهة؛ القيمة المتاحة سابقاً ليست URL صالحاً. |
| حرجة | اختيار نمط جلسة الإنتاج وضبط CORS. | المحول الحالي يستعمل Bearer token داخل جلسة المتصفح للتجربة؛ يظل قرار جلسة HTTP-only أو تدابير الحماية المكافئة مطلوباً قبل الإطلاق التجاري. |
| حرجة | دول الإطلاق، العملات، مزود الدفع لكل دولة، وأسرار Webhook. | يتوفر محول HMAC مرجعي للاختبار فقط، لكنه لا يغني عن محول Checkout وتوقيع رسميين للمزود الذي سيعالج Mada/Visa/Mastercard/Apple Pay. |
| حرجة | S3 أو مزود متوافق حقيقي ومفاتيحه وسياسات الوصول الخاصة. | رفع الوسائط الخاصة لا يكتمل تشغيلياً دون تخزين إنتاجي. |
| عالية | حسابات SPL أو Aramex أو DHL، المفاتيح، وسياسة المناطق والتسعير. | طبقة الشحن الحالية مجال/تكامل جاهز وليست اتصالاً بمزود حقيقي. |
| عالية | اختبار ضغط واسع من عدة workers، مراجعة أمنية، وإعادة تشغيل WebSocket. | اختبار التنازع متعدد العمليات موجود، لكن ذلك لا يغني عن قياس الأداء تحت الحمل الواقعي. |

## الخطوة العملية التالية

الخطوة التالية هي أن يعيد مالك الحساب محاولة الدخول من الموقع العام بعد تحديثه، من دون إرسال كلمة المرور في أي رسالة. ستظهر الآن رسالة محددة إن كان السوق المختار لا يطابق سوق الحساب، أو رسالة تحقق من بيانات الدخول. بعد نجاح الدخول، يُختبر مسار المنتج وجدولة المزاد عملياً، ثم يعاد التحقق من لوحة الإدارة قبل أي قرار نهائي بشأن قاعدة Render القديمة.[1] [2]
