## الملخص التنفيذي

المنصة أصبحت الآن **قابلة للمشاهدة والتصفح** عبر واجهة عربية متجاوبة باسم **مِزَاد**. تتضمن الصفحة العامة اكتشاف المزادات، البحث، فلاتر الفئات، سياق الدولة، بطاقات المزادات، صفحة تفاصيل المزاد، ومساحة حساب المستخدم. ولغرض إظهار التجربة فوراً، تم تعبئة الواجهة ببيانات عرض مؤقتة معزولة في مصدر واحد؛ وهي ليست بيانات تجارية أو مالية أو مستخدمين حقيقيين.

في الخلفية، يوجد مشروع Laravel مستقل به بنية مزاد متعددة الدول، حماية لسياق الدولة، مزايدة ذرية، دورة مزاد، طلبات، تسوية أساسية، محافظ، شحن، بحث، إشعارات، وسجل حوكمة. هذا يعني أن **أساس المجال والخدمات موجود**، لكن ربط الواجهة المنشورة بخدمة Laravel الحية يتطلب أولاً عنوان API يمكن للمتصفح الوصول إليه وإعدادات تكامل تشغيلية.

> الواجهة المنشورة هي واجهة Marketplace فعلية قابلة للتصفح، وليست دليلاً على جاهزية المدفوعات أو الشحن أو المزايدات المالية الحقيقية للإطلاق التجاري.

## ما يمكن رؤيته الآن

| المسار | الحالة | ما يظهر للمستخدم |
|---|---|---|
| `/` | مكتمل للعرض | صفحة رئيسية عربية، اختيار دولة للعرض، حقل بحث، فلاتر فئات، بطاقات مزادات حية، دعوة للبيع، وصف لخطوات المزاد. |
| `/auction/1` | مكتمل للعرض | تفاصيل قطعة، سعر ووقت، إدخال مزايدة تجريبي، حفظ تجريبي، سجل مزايدات موسوم بأنه مؤقت، وتسليم وحماية عرض. |
| `/account` | مكتمل للعرض | ملخص المحفوظات والمزايدات النشطة، طلبات عرض، محفظة عرض، وإشعارات عرض. |
| أي مسار غير موجود | مكتمل | صفحة 404 عربية متسقة مع هوية مِزَاد ودعوة للعودة إلى المزادات. |

واجهة العرض متجاوبة وتمت معاينتها على سطح المكتب والهاتف. النصوص التي قد توحي بحالة تجارية فعلية موسومة بعبارات مثل **«بيانات عرض مؤقتة»** أو **«عرض مؤقت»**، وتفاعلات المزايدة والحفظ لا تنفذ أي عملية مالية أو مزايدة على الخادم.

## ما تم إنجازه في Laravel

| المجال | المنجز فعلياً | ملاحظات حالة الإطلاق |
|---|---|---|
| البنية | Laravel/PHP 8.3، PostgreSQL، Redis، Horizon، Reverb، Meilisearch، MinIO/S3، وخدمات Docker Compose محلية. | Docker Compose مهيأ للمطور المحلي؛ لم تُشغّل خدمات Docker داخل بيئة البناء الحالية. |
| نطاق الدولة والأمن | `X-Marketplace-Country` إلزامية داخل المسارات المقيدة، سياق سوق، Sanctum، RBAC عبر Spatie، Policies، وRate Limits. | الواجهة لا تزال غير متصلة بهذه المصادقة وسياق الدولة الحي. |
| المنتجات والوسائط | مسودات منتجات، انتقال للمراجعة، اعتماد/رفض، ورفع وسائط S3-compatible خاصة. | تحرير المنتج، حذف الوسائط، وتنزيلات موقعة وإدارة مرجعيات كاملة ما زالت أعمالاً لاحقة. |
| المزادات | إنشاء مقيّد، بدء/إغلاق مجدول، إلغاء آمن، سجل مزايدات، اختيار فائز، وإنشاء طلب idempotent. | اختبار تنازع المزايدات عبر عدة Workers مستقلين ما زال ضمن تقوية ما قبل الإطلاق. |
| الدفع والمحافظ | عقد بوابة دفع بحسب الدولة، إنشاء عملية دفع، معالجة Webhook idempotent، قيود أرباح البائع، وسحوبات. | لا يوجد مزود دفع حي أو تحقق توقيع إنتاجي قبل اختيار الدول والمزودين. |
| الشحن | إنشاء شحنة للطلبات المدفوعة، ناقل خارجي/داخلي/استلام ذاتي، انتقالات تتبع وتسليم. | لا يوجد تكامل Carrier API فعلي بعد. |
| البحث والثقة | بحث قوائم مقيّد بالدولة، فلاتر مدينة وفئة وحالة وسعر، شروط أهلية مراجعة، وصندوق إشعارات. | لا توجد مراجعات مرئية أو مزيفة في الواجهة. |
| الحوكمة | نشاط مزايدات بعد الالتزام، سجل تدقيق، وإشارة سرعة مزايدة مشبوهة قابلة للمراجعة. | الإشارة مراجعة فقط وليست محرك منع أو قرار آلي. |

## بيانات العرض المؤقتة

توجد البيانات في `client/src/data/marketplaceDemo.ts`، وهو المصدر الوحيد لبطاقات المنتجات، سجل المزايدات، ملخصات الحساب، الطلبات، المحفظة، والتنبيهات المؤقتة. كما يوثق الملف [FRONTEND_DEMO_DATA.md](./FRONTEND_DEMO_DATA.md) حدود الاستبدال.

لا يحتوي مصدر العرض على **مراجعات، تقييمات، أو شهادات مستخدمين مزيفة**. عند توفر API حية، يستبدل مصدر العرض بمحولات تتصل بالعقود التالية مع المحافظة على مكونات الواجهة:

| وظيفة الواجهة | العقد المستهدف في Laravel |
|---|---|
| اختيار الدولة | `GET /api/marketplaces/countries` ثم إرسال رقم الدولة في `X-Marketplace-Country`. |
| الاستكشاف والبحث | `GET /api/auctions` أو `GET /api/listings/search`. |
| تفاصيل المزاد والسجل | `GET /api/auctions/{auction}` و`GET /api/auctions/{auction}/bids`. |
| المزايدة | `POST /api/auctions/{auction}/bids` بعد ربط Sanctum والسياق. |
| الحساب | عقود الإشعارات والمحافظ والطلبات المتاحة بعد تأمين مسار Laravel للويب. |

## ما يمنع الإطلاق التجاري حالياً

توجد فجوات محددة يجب إغلاقها قبل إطلاق Marketplace تجاري حقيقي. أهمها تحديد الدول الأولى والمزودين الفعليين للدفع والشحن، ثم تشغيل Laravel بشكل يمكن للواجهة المنشورة الوصول إليه وربط Sanctum وCORS وReverb ومسار API بصورة آمنة. لا يصح تحويل أزرار المزايدة أو الدفع من العرض إلى التنفيذ قبل إغلاق هذه النقاط.

| الأولوية | الإجراء المطلوب | السبب |
|---|---|---|
| حرجة | تحديد الدول الأولى، العملات، بوابات الدفع، والناقلين. | قواعد التسوية والشحن مرتبطة بالدولة ولا يمكن تخمينها. |
| حرجة | توفير عنوان Laravel API آمن ومتاح للمتصفح. | لتحويل الواجهة من بيانات العرض إلى بيانات حية. |
| حرجة | ربط المصادقة والسياق والبث اللحظي في الواجهة. | لتنفيذ المزايدة الحقيقية وحالات المزاد الفعلية. |
| عالية | استكمال إدارة المنتجات والوسائط والمرجعيات الإدارية. | لتمكين البائعين وفريق العمليات من تشغيل الكتالوج. |
| عالية | اختبار تنازع مزايدات متعدد العمال، مراجعة أمنية، واختبارات أداء. | لتقوية المسار المالي والتشغيلي قبل الإطلاق. |
| عالية | بناء واجهة الإدارة والتقارير التشغيلية. | لإدارة المراجعة والاحتيال والطلبات والشحن. |

## التوصية بالخطوة التالية

ابدأ بتحديد **دولة الإطلاق الأولى** ومزود الدفع والناقل المقصودين، ثم وفّر عنوان API لخدمة Laravel. بعد ذلك يمكن استبدال مصدر العرض في الواجهة تدريجياً ببيانات حيّة: الدول، الاستكشاف، التفاصيل، ثم تسجيل الدخول والمزايدة والإشعارات. بهذا الترتيب تبقى الواجهة المرئية الحالية مستقرة ولا يتم تشغيل أي تعامل تجاري على بيانات تجريبية.
